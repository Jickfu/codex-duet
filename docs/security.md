# Security boundary

## M3.3 provider and Discussion safety

New tasks select one Browser provider in an immutable local sidecar before any send. A provider mismatch fails closed and never triggers fallback. Codex Browser sends are prepared durably, then marked `ATTEMPTED` immediately before UI action; unresolved attempts and uncertain outcomes forbid automatic replay. A confirmed send requires an allowlisted stable conversation identity reserved across both providers.

Discussion accepts only strict DiscussionResponseV1 bound to the exact task, lifecycle iteration, round, selected provider, TaskSpec fingerprint, and request fingerprint. It is capped at three rounds and cannot be parsed as C2C, transition to PLAN, or authorize workspace writes. Historical tasks without the M3.3 sidecar retain frozen behavior and are not silently migrated.

Codex is the executor. ChatGPT is never authorized to mutate the local workspace, execute a command, or operate Git. Browser automation neither uses private ChatGPT APIs nor automates login, reads credentials, exports cookies/tokens, or records authentication material.

The managed browser profile is isolated under `.chatbridge/profile` and excluded from Git. Normal operation stores no screenshots, DOM dumps, accessibility trees, or full chat history. Future debug artifacts must be opt-in, redacted, bounded, and kept outside published files; screenshots require a separate explicit switch.

Existing-browser attachment has a larger trust surface. A mandatory origin policy defaults to `https://chatgpt.com`. Discovery may enumerate page URLs, but adapter operations reject other origins before locator access or page evaluation. The bridge does not read non-ChatGPT DOM, cookies, local/session storage, storage state, or authentication data, and detach never closes the user's browser. Managed mode never uses the user's default Chrome/Edge profile.

M3.2a task conversation binding is Browser Control Plane routing metadata. Its gitignored task sidecar may contain only a validated task ID, exact allowlisted conversation URL, stable message IDs, timestamps, and minimal binding state. It must not contain prompt or response text, DOM, HTML, accessibility trees, screenshots, cookies, credentials, auth tokens, or browser storage. Conversation URLs must be absolute, contain no credentials, and pass the existing `OriginPolicy`; they are structured values and are never concatenated into shell commands. Exact-target navigation is validated before and after navigation. A missing or inaccessible bound conversation fails closed and never falls back to another ChatGPT tab.

Project-wide active-task uniqueness must be serialized so two non-terminal tasks cannot race to claim the same conversation. Terminal tasks release exclusivity while retaining historical evidence. Binding is immutable by default; automatic rebind is forbidden.

M3.2b execution evidence is separate, iteration-scoped, gitignored orchestration metadata. It may contain only task and iteration identity, plan hash, task branch, full baseline `HEAD`, start time, and optional test status bound to an exact full `HEAD`. It must not contain source snapshots, diff bodies, command logs, environment dumps, credentials, secrets, or arbitrary external-effect journals. Execution inspection uses read-only Git operations and must never reset, clean, stash, checkout, commit, or push.

M3.2c stores the plaintext raw request, strict normalized TaskSpec, and compact `task-context.json` marker only in gitignored `.chatbridge/runs/<taskId>/` state. The marker contains task ID plus TaskSpec and first-Planner-control fingerprints, never raw request content. Neither request nor TaskSpec is automatically committed, pushed, attached, or copied into debug logs. Exact Planner/Reviewer projections may contain only minimum necessary task semantics and durable identity; logs expose byte counts and fingerprints, not bodies. TaskSpec integrity hashes detect changes but do not make sensitive content safe to publish. Missing or mismatched marked semantic evidence fails closed before normal M2 push. Phase 1 adds no encryption, key management, attachment upload, or secret-bearing context provider.

Crash reconciliation proves only Git-visible repository-development state plus explicit durable test and Frozen M2 evidence. It cannot prove whether arbitrary database, deployment, network, publishing, cloud, or shell side effects occurred. Such effects remain `UNVERIFIED`; non-idempotent replay fails closed. Dirty work is preserved, test PASS is never inferred, divergent history is never repaired automatically, and only conclusive already-completed Frozen M2 work may advance M3 durable state without repeating the external operation.

Every adapter operation owns a permanently invalidating main-frame navigation guard and captures an ElementHandle for the original document. Every DOM read or side effect is checked before and after it runs. After an allowlisted-origin escape, no new action starts, no locator can retarget the foreign document, and results from an in-flight Playwright primitive are discarded. Playwright does not expose a universal AbortSignal for all DOM primitives, so codex-duet does not claim physical cancellation of a primitive already executing; the security guarantee is document binding, permanent operation invalidation, and no subsequent foreign-origin DOM access. Agent CLI run-code applies the same checks. CLI stdout/snapshots are captured by the runner and never returned through the control plane; only structured results or redacted errors escape.

The LOCAL MCP boundary is permanently read-only for workspace content. It enforces canonical workspace-root containment, traversal and symlink-escape prevention, bounded requests/responses, task/snapshot/iteration identity, state transitions and secret-safe errors. `submit_response` may write only `.chatbridge` internal task/run state outside the workspace content surface and is disabled unless explicitly composed with an exact task/control capability. No `write_file`, `delete_file`, `shell`, `exec`, `git_commit`, or `git_push` tool is exposed.

The independent deny policy covers `.env`, key/certificate stores, SSH/cloud credential locations, package credential files, `.git` and `.chatbridge`. Credential payload names include password/secret/token/credential families, client secrets, access/refresh/auth tokens and API keys: extensionless or hidden names, plus JSON, YAML, TOML, INI, CONF, TXT and ENV payloads, including deployment suffixes such as `secrets.local.json`. Normal source names such as `SecretService.ts`, `token-parser.ts` and `secrets.ts` are not denied just for mentioning credentials. This is a filename/location policy, not a content secret scanner: secrets embedded in otherwise allowed source remain the operator's responsibility. A task requiring a denied path is not reviewable through this default surface.

The M4 loopback server is an explicitly started library within the local-machine trust boundary. It rejects non-loopback listen addresses and foreign Host/Origin headers; it is not a public authenticated read service. Do not expose it through a tunnel or reverse proxy as an M4 workaround. M5 uses a separate [authenticated development listener](remote-local-mode.md): local operator approval, authorization code with S256 PKCE, lifetime-scoped opaque tokens, exact task/snapshot/iteration grants and an owned cloudflared supervisor. Its eight read tools exclude `submit_response`. Real ChatGPT acceptance remains pending; this is not a production identity service.

The GITHUB mode does not expose a local workspace or run a local bridge/tunnel. Reviews identify immutable commit SHAs.
